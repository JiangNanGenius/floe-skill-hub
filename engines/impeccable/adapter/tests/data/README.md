# Adapter test data

Derived test inputs for the Rust integration tests. These are **not** contract
fixtures: the frozen contract fixtures live in
`engines/impeccable/contract/fixtures/` and are the artifacts native (A2) codes
against, so the adapter's tests must not require new files there.

| File | What it is |
| --- | --- |
| `snapshot-no-findings.v1.json` | the contract's positive page with body copy at 16px/24px, so the run has nothing to report; proves an empty finding list is `inconclusive`, never `clean` |
| `identity-no-findings.v1.json` | identity bound to that snapshot |
| `snapshot-media-intrinsics.v1.json` | the same page plus an `<img>` carrying media intrinsics; exercises the `media-intrinsics` coverage state |
| `identity-media.v1.json` | identity bound to that snapshot |
| `facts-unanswerable-template.v1.json` | shape example for a facts file whose points are all unanswerable (the tests build the real one from an observed Needs) |
| `facts-positive-round2.v1.json` | reference answers for the contract's positive fixture (183 points) |
| `facts-overlay-round2.v1.json` | reference answers for the overlay fixture (169 points) |
| `facts-no-findings-round2.v1.json` | reference answers for the no-findings snapshot (169 points) |
| `facts-media-round2.v1.json` | reference answers for the media snapshot (186 points) |

## How the facts files were produced

The hit-test points are decided by the rules, so a facts file can only come from
an observed `needs`. They were generated by the contract's reference answerer
against the host build of this engine at the pinned upstream commit:

```bash
# 1. derived snapshots and identities
python3 engines/impeccable/adapter/tools/make_test_snapshots.py \
    --upstream <pinned-source-dir>

# 2. observed needs -> reference answers -> observed round-2 result
python3 engines/impeccable/contract/tools/observe_and_complete.py \
    --engine <host-or-guest floe-impeccable> \
    --contract engines/impeccable/contract \
    --out <scratch> \
    --case positive=fixtures/snapshot-positive.v1.json,fixtures/identity-positive.v1.json \
    --case overlay=fixtures/snapshot-needs-hit-tests.v1.json,fixtures/identity-needs.v1.json
python3 engines/impeccable/contract/tools/observe_and_complete.py \
    --engine <binary> --contract engines/impeccable/adapter/tests/data --out <scratch> \
    --case no-findings=snapshot-no-findings.v1.json,identity-no-findings.v1.json \
    --case media=snapshot-media-intrinsics.v1.json,identity-media.v1.json
```

The reference answerer (`observe_and_complete.py`) answers each point with a
geometric hit test over the same snapshot: the deepest painted element whose box
contains the point, then its ancestor chain, which is what
`elementFromPoint`/`elementsFromPoint` return on a page without stacking-context
surprises. The real native producer answers from WebKit instead.

## Why the derived facts are checked in

They are a **regression gate**: if an upstream engine update changes which points
the rules ask for, `facts-*-round2.v1.json` no longer answers them, the round-2
tests stop converging, and the updater workflow fails instead of silently
shipping an engine whose Needs shape moved. Regenerate with the commands above
only after that change has been reviewed.

## Limiter regression fixtures (2026-10-26)

`snapshot-large-shape.v1.json` / `snapshot-admission.v1.json` (with their
`identity-*.v1.json`) are synthetic pages generated by
`tools/make_regression_fixtures.py` — never derived from a private capture
packet. The large shape mimics the *public structure* of the large-capture
diagnosis (~2000 sections of short heading + long paragraph, 980x735
viewport, ~124k px page, all-static styles, no recorded hits); the admission
grid is a dense field of small visible text boxes whose unique probe misses
cross the per-round cap. `expected-*.v1.json` are the recorded result
documents of the PRE-PATCH adapter (1.0.0) on the same fixtures
(`tests/rule_pass_limiter.rs` reruns them and requires byte-equality after
wall-clock and engine-identity normalization). Regenerate the fixtures with:

```
python3 engines/impeccable/adapter/tools/make_regression_fixtures.py \
    --upstream <pinned-source-dir> --out engines/impeccable/adapter/tests/data
```

and the goldens by running the pre-patch host binary on them (see the
Floe engine 1.1.0 source-repair lane handoff, retained in Floe private records).
Note: `needs.scrollProbes` is empty in every snapshot-scan result today —
no rule in the snapshot pass asks `shown_when_scrolled_to` (the hidden-text
measure that asks it is not routed by the Floe adapter), which the expected
files record honestly.
