# Floe Skill Hub 与 MCP 创建向导实施计划

日期：2026-10-26。状态：最终实施计划；本文不表示功能、目录或网站已经发布。

本轮一起交付两条能力：独立 Skill Hub 的内容、分发及客户端接入，以及融合进 Floe MCP 组件的服务创建与测试向导。目标是进入 iOS 主线同一个新 build，复用一次最终集成和相关 App 验收。官网使用同一版目录，部署状态单独记录。Android 沿主线同步，不在本线程另行发起 Android 实施或发版。

## 1. 交付边界和所有权

| 交付物 | 本线程 | iOS 主线 |

## 2. 首批内容和精选标准

首版目标 43 项，其中 4 项继续随 App 内置，39 项按需安装。每项必须提供一个完整用途；不拆命令凑数，不把系统设置包装成商品。

许可可分发、来源可追溯和安全行为是前置条件。通过前置核验后，按实际用途 25%、Floe 兼容性 25%、内容与示例质量 20%、维护情况 15%、社区采用情况 10%、互补性 5% 综合评定。记录评分理由和采集日期；上游仓库星数不能当成某个技能自己的评分。主分类用于导航，标签用于跨场景检索。

### 3.1 Impeccable 的实现边界

完整上游源码不进入 App 主仓或 Skill Hub Git 历史。构建时读取固定提交，新仓只保存来源锁、构建脚本、必要补丁、许可和版本化 RISC-V 引擎。引擎作为单独签名目录认可的运行依赖，不塞入 skill ZIP；保留现有对 ELF、原生库和包体积的校验。规范化上游 `reference/` 等目录时一并更新内部引用，保留版权与修改记录。

优先编译完整 CLI 中首版实际使用的路径；若上游自更新、安装器或网络依赖阻碍交叉编译，以显式构建功能裁剪这些由 Floe 自己管理的部分，继续保留首版承诺的上下文、静态检查与快照规则能力。不能用仅有规则内核的二进制冒充完整 CLI。产物绑定上游提交、适配版本、ABI、工具链和摘要，必须在 Floe 实际 RISC-V 客体中运行；QEMU 用户态测试只是补充。

网页检查采用受控数据交接，不伪装完整 CDP：原生端使用固定、审核过的 WebKit 测量代码，在隔离内容世界导出页面样式、几何和所需状态；引擎复用上游 SnapshotDom 及规则实现。上游返回缺失 hit-test facts 时，原生端在同一页面身份下补充并重跑。页面导航、视口或滚动状态变化使原快照失效；有明确的有界迭代及失败原因，不能把缺失测量当成检查通过。

最小新增接口由主线实现为现有 `browser.observe` 的可选 `profile: design`，默认观察行为不变。设计模式返回与当前 session/tab/document 绑定的快照产物引用、摘要、视口及覆盖说明；原生内部受控操作负责按快照节点回答额外测量。模型不获得任意 JavaScript 执行口或通用私网 CDP 端口。快照和测量结果通过任务所属工作区或已解析环境的安全文件桥交接，禁止临时选择其他任务的工作区。

首版快照规则覆盖不等于上游 Chromium URL 全流程。像素级对比度、滚动揭示/遮挡操作、跨源 iframe 等未实现覆盖必须明确列出；不能把缺少事实的规则改成绿灯。浏览器交互继续通过已有工具执行。后续若扩展这些检查，单独补测，不把它们写成首版已经支持。

### 3.2 Impeccable 自动跟进

Skill Hub 的 GitHub Actions 每日检查上游正式版本，同时支持手动触发。匹配 skill 与引擎版本后生成更新 PR，执行固定源码构建、规则回归和快照契约测试。构建任务不接触签名密钥；PR 通过审核和必要的实际环境验证后，才进入签名发布流程。失败保留原可用版本，不自动替换安装中的引擎，不跟随未经审核的上游 main。

## 4. MCP Builder 融入系统组件

在既有 MCP 入口增加“创建服务”，不增加商店项目或第二套 MCP 管理。前半段是需求与项目生成向导，后半段继续使用已有的连接配置、凭据、工具发现、调用和启停机制。

首版流程：选择任务所属项目及 Linux 环境 → 描述目标、输入输出和所需外部服务 → 生成项目与测试 → 安装固定依赖并启动 → 完成真实客户端验证 → 显示测试摘要并通过现有保存/启用操作接入。

- 首版默认模板为 TypeScript/Node 与官方 MCP SDK，采用现有客户端可接入的 Streamable HTTP。不增加 App 内执行代码、宿主解释器回退或第二套 stdio 服务托管。
- 上游 MCP Builder 的方法与模板保留许可及修改记录，适配资源随 App 的现有 MCP 功能归属管理，不作为远程 skill 安装来扩展原生功能。
- 项目生成使用当前任务绑定的模型配置，复用已有工具与工作区变更审阅。上游 Anthropic SDK 评测脚本不直接带入另一套模型调用或索要额外模型密钥。
- 服务关联明确的 environmentID、项目、持久化项目目录及现有服务句柄；endpoint 由真实监听和受控转发得到，不猜端口，也不把停止的服务显示为可用。
- 安装和测试使用现有 jobs/service 生命周期。处理取消、依赖失败、服务异常退出、App 重启后的真实状态恢复，以及停止/删除环境时的引用清理。
- 向导输出包含项目位置、锁定依赖、服务/环境身份、实际 endpoint、测试记录及 MCP 连接草稿。未通过测试不自动启用。
- 最低验收为编译/类型检查、initialize、工具列表和参数 schema 校验，以及一个明确只读的测试工具真实调用。生成的业务工具若有外部副作用，测试遵守既有权限，不为验收自动执行真实发送或删除。
- 不只验收“生成代码成功”：还要从现有 MCP 组件发现并调用工具，停止服务后正确变为不可用，再启动后恢复连接。

## 5. 新仓目录和旧版兼容

新仓是唯一维护来源。复用当前 Ed25519 信任体系，保持签名目录 → ZIP 摘要 → 解包内容摘要的链路，不另造包内自授信任根。新增目录在保留发布者、包身份、版本、大小、摘要、最低 App 版本和变更记录的基础上，增加展示元数据、实际平台/运行条件、媒体来源和独立依赖引用；字段形状与主线已实现的平台契约一起固定。

新客户端将“受保护的四个内置官方 ID”与“可浏览的精选目录”分开，不再以四项集合限制整个商店。脚本未验证时不能宣称可运行；只读指南是否可安装仍遵循主线既有兼容策略。

### 5.1 模型从商店按需获取

模型能够完成“搜索商店 → 读取详情 → 安装所需项 → 在当前任务读取并使用”的闭环，不要求用户预先手动打开商店，不把安装成功等同于运行成功。

- 扩展现有 `skill.search` 的可选 `source: installed | hub | all`，省略仍保持现有 installed 行为；现有 query/queries 参数兼容。Hub 返回通过签名校验的元数据、准确 ID/版本、目录提交、安装与启用状态、兼容条件、所需权限、运行依赖及适配状态。查询优先复用有效本地索引，不为每次搜索下载全部包。
- 扩展 `skill.read` 的可选 `source`；省略仍读取已安装技能并保留现有分页、资源暂存及任务快照行为。Hub 读取返回固定版本的用途、示例、审核权限和依赖详情，明确标记“未安装”，不激活指令或暂存未安装脚本为可执行资源。
- 为同一个 `skill.install` 增加互斥的 Hub 请求分支：`source: hub`、`id`、`version`、`publicationCommit`（单次解析得到的发布提交 Y）；回执另记签名目录的 `sourceCommit`（审核出处 X）。原有仅 directory 的工作区安装请求和替换摘要规则保持兼容。Hub 分支由可信服务解析固定签名目录、下载、校验、暂存和提交，不能转成普通工作区导入来绕过官方来源保护；不接受模型提供的任意下载 URL 或自称可信的标记。
- 同一可信来源、同一版本已经安装时返回可核验的复用结果；较新版本不降级。同名的本地技能或不同来源包不自动覆盖。用户明确停用/卸载、修改过的技能按现有管理和授权流程处理，不被搜索结果静默恢复。官方更新复用现有来源升级事务，不把 `skill.manage` 的指令编辑误作远程版本升级。
- 安装完成后立即更新可发现元数据；当前任务可通过 `skill.read` 获取新技能并暂存完整资源，无需新开会话。此前已经加载的同 ID 快照和其他运行中任务不被改写；权限上限及任务/环境归属继续有效。
- 仅下载当前任务需要的包和缺失依赖，执行依赖进入已解析的 Linux 写层。服务报告真实安装、依赖和执行结果；依赖不兼容、断网、取消、下载损坏、安装失败与权限不足分别说明，保留可恢复版本。

### 5.2 精选审核与默认放行

商店权限审核由维护者在上架前完成，用户不为每项重复审核同一权限。**固定版本通过商店审核，且其全部所需权限已由用户授予并在当前任务/环境范围内有效时，模型搜索后直接下载、安装、启用和使用，不再出现单项安装确认。** 对没有新增权限的已审核更新同样放行；实际执行仍在用户授权的任务范围内。

- 审核记录绑定技能 ID、版本、内容摘要、声明工具/权限和运行依赖，受可信签名目录保护。包自身文本、上游 README 或模型参数不能赋予审核状态。
- 使用现有授权存储和权限判断，不新增一套互不一致的商店权限库。将该版本所需权限与用户有效授权相减；只有首次缺少、版本新增、授权被撤回或原授权范围不适用的部分，才进入一次合并的增量授权。用户拒绝后不在工具重试中连续弹同一请求。
- 原生宿主依据已验证目录和现有授权产生放行依据。当前 `skill.install` 对工作区包要求显式 approval 的行为不变；Hub 分支不能要求模型伪造 approvalGrantID，也不能全局删除安装审批检查。
- 自动启用适用于新安装且已授权的商店技能；此前明确停用、卸载或撤销授权的选择优先，不能把“默认放行”解释为恢复用户拒绝过的内容。
- OS 级权限、外部账户授权和凭据仍使用对应系统/现有服务。临时聊天保持原有只读及公共网络上限，不能安装技能、启动 guest 或持久化资源。
- 必测：已有授权全程无重复弹窗；无权限技能直接获取；多个缺失权限合并请求；拒绝/撤销不反复请求；无权限变更更新自动放行；权限扩大只请求新增部分；签名或包摘要变化使原审核记录失效。

四个官方技能迁入新仓管理，但 App 保存固定提交导入的离线副本，普通 App 构建不依赖在线拉取。保留原 ID、内容摘要、停用/卸载选择、本地修改和正在执行的快照；较新的已安装版本不降级。迁移基线同时包含已发布和待发布内容，Office 源码 1.4.0 与已发布 1.3.0 不混为同一状态；执行时先核实主线最新基线。

原主仓的历史目录、签名及包保持可用，旧 iOS 客户端继续收到旧格式的四项兼容视图。新仓生成兼容视图，由 App 主线现有发布所有者更新，不在两个仓库独立改源码。保留主线已建立的 iOS/Android 分频道规则及旧入口；不存在真实签名产物前，不把客户端指向空目录。内容中心、模型目录和应用发布流程不随此次拆仓迁走。

## 6. 官网 Skill Hub

App 商店的目录、签名、审核记录、详情、技能包和独立引擎均直接从受信任的 GitHub 仓库获取，同次操作固定同一发布提交；官网只在构建时导入目录并静态展示，不提供 App API、下载代理、CDN、遥测或回退源。GitHub 不可达时，App 沿用已核验的本地缓存与离线状态，不把请求转到官网。

在既有官网新增 `/skills/` 与 `/skills/<id>/`，导航名为 Skill Hub / 技能商店，中英文对齐。沿用已确认的深色、青蓝紫点缀、精选封面加完整目录、图文详情的设计方向；使用真实 Floe 标志和准确文案，修正概念图中的临时内容。

- 首屏三项编辑精选，下面是搜索、七个主分类、标签和完整目录。默认编辑推荐，可按名称和更新时间排序；筛选写入 URL，返回时恢复浏览位置。
- 详情页包含用途、适用场景、示例提示词、输入输出、图片/示例、要求与限制、实际适配状态、作者、许可、版本记录、来源及安装操作。四个自带技能标注“App 已内置”。
- 有分发权的真实运行截图或产物优先，其次是自制、验证过的示例，最后是与用途有关的统一图形封面。无图也有专属图标、图形和排版；示意图不能冒充运行证据。
- 目录与图片从同一已发布版本导入并预渲染，GitHub 临时不可用时仍能浏览最后有效内容。图片缺失、长标题、空结果和无安装能力都有完整状态，不显示失效按钮或虚构评分。
- 桌面、iPad 和手机分别验收；目录多列/双列/单列自适应，支持键盘、可见焦点、替代文本、触控和减少动态效果。列表缩略图延迟加载，详情大图不拖慢首屏。
- iOS 主线提供真实的客户端导入或深链契约后再接线。不存在已实现的深链时使用真实包下载及导入说明，不编造一键安装。

官网代码完成、构建通过、浏览器验收和生产部署是不同状态。沿用既有官网部署边界，不因本计划切换源站、DNS或部署未验收内容。

## 7. 同一个 build 的协调和验收

### 7.1 并行工作线与汇合点

协调者先固定目录、包、依赖、权限审核、快照和 MCP 交接契约，并交付可验证的目录样本；此后按文件所有权并行推进，不把主线负责人变成逐项串行执行者。

| 工作线 | 独立负责的范围 | 可以立即并行的工作 | 必须等待的汇合输入 |
| --- | --- | --- | --- |
| H1 新仓与目录 | Hub 构建器、目录元数据、审核记录、签名、旧版兼容视图 | 固定格式、来源锁与校验；普通/深度技能先用已锁定样本接入 | 各内容线的冻结包和真实验证结果，统一生成最终签名目录 |
| H2 普通技能 | 除下列九项外的逐项来源/许可/内容与脚本适配 | 按互不重叠的技能目录分批核验与验证，不等待 Impeccable 完成 | 共用执行依赖及最终构建器契约 |
| H3 网页技能适配 | H3a：Impeccable 引擎引用、补丁、RISC-V 构建、启动器与快照；H3b：`webapp-testing` 复用既有原生浏览器与任务服务 | 引擎与网页测试包分为独立交接和文件范围；网页测试不安装 RISC-V 不支持的浏览器，也不以 HTTP 检查冒充 UI 验证 | A2 真实快照与文件桥、既有浏览器操作接口，用于实际客体和页面闭环 |
| H4 数据与文档 | 数据探索、统计、可视化、Markdown 转换、文献综述 | 建立共用的最小依赖与样例，按技能目录独立实现 | 主线冻结的执行/文件桥接口用于 App 最终验证 |
| H5 视觉创作 | 平面视觉设计、生成艺术、字体与示例素材 | 独立产物生成、许可与导出验证 | 原生预览/文件服务的既有或确认后接口 |
| W 官网 | 既有官网的 Skill Hub 页面、详情与封面 | 依据冻结目录样本开发搜索/分类/详情和响应式页面 | 最终签名目录、真实安装入口及已验收媒体 |
| A1 商店及模型获取 | 主线现有 Skills owner 的客户端来源迁移、商店、search/read/install 和授权复用 | 在同一 owner 下合并现有生命周期成果，基于样本独立实现 | H1 固定版本目录及 H3/H4/H5 的依赖与状态 |
| A2 浏览器适配 | 主线 Browser owner 的固定测量、快照/facts 和安全文件交接 | 使用合成页面和冻结格式实现；不等待全部引擎构建 | H3 已构建适配器，完成端到端测试 |
| A3 MCP 系统 | 主线 MCP owner 的创建向导、生成模板、服务与连接接线 | 与 A1/A2 文件范围分开；使用既有模型/环境/服务契约实现 | 模板依赖锁与真实 MCP 客户端测试结果 |

工作线是所有权与交付边界，不等于预先提交九个排队任务。同一 checkout 遵循适用的并发限制；派发前检查当前 worker、空闲容量和实际 scope。先发有具体输入且可独立推进的工作，后续根据就绪结果补位。共享模型/环境/工具协议由主线唯一 owner 改动，其余线提交明确变更请求或私有补丁；共享生成文件由 H1 汇总，项目配置和全 App 构建由主线汇总。

重型编译、共享 guest/Simulator、App 测试和打包按资源锁串行；源码实现、许可/内容核验、独立夹具和官网工作并行。跨线验证前冻结双方输入及摘要；局部产物就绪即可交接，不等所有线写完长报告。

### 7.2 汇合与同批冻结

1. **接口先固定**：主线收取本计划，复用当前技能生命周期与平台目录成果，确认目录增量、浏览器设计快照、环境文件桥、运行依赖安装和 MCP 向导接线的唯一 owner。先交给主线一个固定的可验证目录样本，允许其并行实现界面和客户端。
2. **并行推进**：各线按上表独立实现；Impeccable 构建、数据/文档依赖、视觉素材、官网与三条原生接线不相互串行等待。依赖完成一个就验证并交接一个，不预填未来依赖任务，不让两位 writer 同时修改同一模块。
3. **同批冻结**：九项深度适配、MCP 系统集成、商店客户端与兼容迁移均交付精确源码/包/摘要及聚焦测试后，由主线冻结这一轮版本。当前开发配置观察为 1.7.59（300），不是授权占用的最终编号；若该编号已被其他交付冻结或上传，主线选择新的未使用编号，绝不替换旧产物。
4. **一次最终集成验收**：在同一冻结源码上完成相关本地 Swift 6 App/object 构建、聚焦行为测试及唯一复用 iPad Simulator 的 App 验收。必要的局部编译用于解决真实接口阻碍；不为每个技能重复整套 App 构建、归档或云矩阵。
5. **一致的内容版本**：App、官网和签名目录记录同一份 Hub 提交/目录摘要。官网可与 App 打包并行验收，生产部署与 App 分发分别由相应所有者按授权执行，不将“网页可见”当成客户端可用。

### 7.3 必须具备的证据

| 范围 | 通过条件 |
| --- | --- |
| 每项上架技能 | 来源/许可/依赖完整；代表性任务有真实产物；相关脚本在声明的实际环境执行，指南不冒充执行能力 |
| Impeccable | RISC-V 产物身份和摘要；真实客体执行；静态检查和 WKWebView 快照规则测试；缺失 facts、页面换代、取消及未覆盖规则不会误报通过 |
| 深度适配九项 | 表中首版流程分别完成；原始失败保留；在实际输出中验证文本、图像、图表、引用或转换结果 |
| MCP 系统集成 | 生成、启动、initialize、tools/list、只读 tools/call、保存、停用、恢复、取消和环境删除边界均有结果 |
| 来源迁移 | 新安装离线四项可用；旧客户端原目录不坏；停用/卸载/本地修改/新版本/运行中快照不被错误覆盖；摘要或签名错误拒绝替换 |
| App 商店 | 浏览/搜索/详情/安装/更新/依赖缺失提示在实际 App 验收，跟 UI 草图和模块测试分开 |
| 模型按需获取 | 全新任务直接搜索 Hub、读详情、拉取未安装技能并在同一 run 使用；已有授权不重复确认，缺少/撤销/新增权限和同名冲突有正确结果，临时聊天不能借此扩权 |
| 官网 | 中英文、分类/搜索/详情/图片异常、真实安装入口及三种布局通过浏览器检查；部署另行回读 |
| 构建与清理 | 记录源码、工具链、目标、命令、真实结果和限制；只清理本轮已无用途的输出，保留交付物、原始失败和必要回滚 |

目标是在一个新 build 内完成上述 App 能力，不把 MCP 集成或 Impeccable 静默留到后续版本。若有真实阻碍，封板前向用户说明具体项目与影响，由主线协调范围或编号；不能用修改状态标签代替完成。

执行本计划不扩大历史生产发布授权。版本、完整 App 构建、Simulator、签名上传和发布始终由主线唯一所有者处理；本线程不自行版本递增、提交 App 审核或发布生产网站。
